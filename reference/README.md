# 원본 파이썬 구현

`:domain` 의 **정답지**다. Kotlin 이식은 이 두 파일을 옮긴 것이고,
규칙이 갈리면 **이쪽이 맞다.**

```
python3 reference/streak_sim.py     # 검증 22개 + 60일 시나리오
python3 reference/allocation.py     # 검증 16개
```

두 스크립트 모두 표준 라이브러리만 쓴다.

## 왜 남겨두나

Kotlin 쪽을 고칠 일이 생기면, 고치기 전에 두 구현의 출력을 맞대어 보는 게 가장 확실하다.
이식할 때 실제로 그렇게 검증했다 — 분배 19,100줄, streak 37,604줄이 완전히 일치했다.

차분 검증을 다시 하려면: 같은 입력을 양쪽에 먹이고 하루씩 상태를 찍어서 `diff` 한다.
파이썬 쪽 리스트 표기(`['X']`)와 Kotlin 쪽(`[X]`)만 맞춰주면 된다.

## 주의

- 파이썬에는 **멱등성이 없다.** 같은 날짜를 두 번 `settle()` 하면 streak이 두 번 오른다.
  Kotlin 쪽 `alreadySettled` 가드는 기획 10장 요구로 **덧붙인 것**이라 여기엔 없다.
- `settle()` 의 `note` 인자는 그냥 되돌려주기만 하는 값이라 Kotlin 으로 안 옮겼다.
- `give_shard()` 는 파이썬 주석에 "이전 이름 호환"이라 되어 있어 안 옮겼다.
- 60일 시나리오(`scenario()`)는 검증이 아니라 출력 데모다. `:sim` 모듈이 같은 일을 한다.
  파이썬과 Kotlin 의 난수 생성기가 달라서 **숫자는 다르게 나온다.**
